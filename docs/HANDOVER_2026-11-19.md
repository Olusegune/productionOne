## 1. The project in one paragraph
**Production One** is a Windows-first desktop app (Tauri 2 shell in Rust + React/TypeScript UI) for AI pre-production: you give it a script, pictures, or just an idea; it builds a "production bible" (characters, costumes, props, places), makes reference sheets and storyboard frames with image models (mainly through **Kie.ai**), and packages the result. It is the owner's own project.
- Repo: `https://github.com/Olusegune/productionOne` (clone to e.g. `C:\Users\<you>\code\productionOne`). Default branch `main`.
- **Not** the `pulseframe` folder: the Claude session was started in `C:\Users\eduni\code\pulseframe`, which is a different, unrelated project whose `CLAUDE.md` does not apply here. Work in `productionOne`.
- Owner pronouns: not stated; use they/them.
- The repo's own older handover is `HANDOVER_FOR_CLAUDE.md` (and `PROJECT_STATE.md`); this note is newer and wins where they differ.

## 5. Set up on a new PC
**Install:** Git; Node 22+; Rust stable (MSVC toolchain) with the Windows build tools; WebView2 runtime (ships with Windows 11); for installers, Tauri downloads NSIS/WiX itself on first build. Python 3 (for the release scripts and Pillow for contact sheets: `pip install pillow`). Playwright is only needed for driving the test app (`npm i playwright-core` somewhere; Edge is the browser).

```bash
git clone https://github.com/Olusegune/productionOne
cd productionOne
npm ci
```
**Keys are NOT in the repo** and live in the OS credential store (Windows Credential Manager, service `production-one`, one entry per provider: `kie`, `fal`, `openai`, `google`, `openrouter`, `elevenlabs`, `voicekiller`, `magnific`...). On a new PC re-enter them in the app (Tools > Provider Settings). The Kie key is the one used for nearly all tests.

**GitHub access for releases:** the release scripts read a token with `git credential fill` (whatever Git Credential Manager has stored for github.com). Log in with git once on the new PC (`git push` something) so it is stored. The token needs `repo` scope, and `workflow` scope to push changes to `.github/workflows`.

**Gate commands** (run from the repo; this is "the full gate"):
```bash
npx tsc -p tsconfig.app.json --noEmit      # NOTE: plain `npx tsc --noEmit` checks nothing here (root tsconfig lists no files)
npx vitest run                             # 721 tests at 0.51.0 (1 skipped: the file writer, WRITE_2D_DEMO=1)
npm run build                              # also runs tsc -b
npm audit
cd src-tauri && cargo clippy --all-targets -- -D warnings && cargo test    # 101 tests
```
CI (`.github/workflows/ci.yml`) runs vitest, build, accessibility QA and `cargo test` on Windows for every push.

## 9. Gotchas that cost time (so you can skip them)
- **Use the Write tool, not bash heredocs, for any code containing backslashes or quotes.** The shell layer here halved backslashes (a regex `\b` became a backspace character; this shipped once in 0.48.0 and was fixed in 0.50.0). For multi-line Python edits, write a `.py` file and run it.
- Files in this repo mix **CRLF and LF**; edit scripts normalise (`replace('\r\n','\n')`) and write back the original style. Git warns about line endings; it is harmless.
- Version-sync test needs the changelog heading and `RELEASE_NOTES_<version>.md` to exist, or `vitest` fails with one test.
- Order of nav tabs matters for shortcuts: new workspaces are appended at the end (`src/components/shell.tsx` `workspaceNames`).
- Kie: generation fetches the model's docs page first; since 0.50.1 it is cached for 6 hours. Kie error text is shown in the UI; the app's own notice is hidden behind full-screen panels, so panels show their own result line.
- The queue's `committedUsd` is an estimate from the person's own price; it is never a bill.
- GitHub macOS Intel runner label is `macos-15-intel` (`macos-13` no longer exists).
- Closing a PR-bound branch: the task tooling's "bind PR" refused this repo; PRs are tracked with the ship scripts instead.
