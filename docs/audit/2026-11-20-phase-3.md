# Phase 3 audit: spatial records and visual review (2026-11-20)

## Current state
- Shots (`direct.ts`) had no world positions; `checkContinuity` only compared shot facts (screen direction, set, looks). No notion of furniture ownership or who sits where.
- Review (`ReviewView`) shows one picture next to the approved reference; technical QA exists (`qa_image`, notes on jobs) but there are no categorised findings, no status beyond approve/reject, and no correction records.
- The queue (`enqueue`) already creates a new revision per regenerate and never overwrites; `Provenance` (Phase 2) carries the proportion profile and references.
- Local vision-capable models can be reached through `local_llm` (images supported, up to 6).

## Decisions
- Scene state is stored per scene with world, intentional changes and per-shot cameras kept apart; screen placement is derived.
- Findings from rules and from a model live in separate lists. "Not checked" is the default and is never shown as clean; "Passed" names the categories checked.
- Vision review is opt-in and uses only a local model (no spend). Reading the answer is strict; failure is "unable to assess".
- Corrections regenerate one view (no adapter supports inpainting); bounded to 3 attempts and $1.00 per finding; always wait for approval.
