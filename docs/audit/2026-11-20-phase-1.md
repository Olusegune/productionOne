# Phase 1 audit: proportion profiles (2026-11-20)

## Repo commands (there is no AGENTS.md and no lint script)
- Type check: `npx tsc --noEmit -p .` (also part of `npm run build` = `tsc -b && vite build`)
- Tests: `npm test` (vitest) and `cargo test --lib` in `src-tauri`
- Build: `npm run build`; desktop installers `npx tauri build`
- Security: `rafter secrets .`; `rafter run` (remote, quota limited)

## Current state for this scope
- No proportion concept exists. The only mentions are fixed prompt sentences ("keep the same body proportions", "consistent scale and proportions") in `sheetSpecs.ts` and `productionStudio.ts`.
- Project state is `StudioState` in `src/data/projectStore.ts`, saved in the `.pone` file (`src/data/projectFile.ts`, format version 1). Its later fields are optional, so an optional field needs no version bump and old files load unchanged.
- Character identity fields live on `ExtractedAsset` (`productionStudio.ts`); style is `StyleBible` (`visualDevelopment.ts`) with a per-asset override. Neither holds anatomy.
- Design screen: `DesignView.tsx` has the Identity tab (`AssetLab`); image jobs go through `generationQueue.ts` (`enqueue`).
- Golden Path: `src/domain/goldenPath.ts`, derived from project data.
- Camera in `direct.ts`: size, angle, lens (a default per size), movement. Lighting is one string. No grading. (Phases 4 and 5.)

## Decisions
- The profile is a new optional map `studio.proportions`; no new project version.
- It is opt-in per character. A character without one is untouched, so existing projects render identically (golden test over a saved 0.51.2 project's prompts).
- Phase 1 changes no prompt. Wording from a profile is used in Phase 2.
- The Golden Path gets an optional "Shape" extra that appears only after a profile exists, never blocks and never counts toward progress.
